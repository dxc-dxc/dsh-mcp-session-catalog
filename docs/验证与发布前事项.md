## 本轮审查和修复

审查范围为核心源码、连接池、安装补丁、包内容与文档，使用一次独立只读对抗审查并逐项核对源码。

| 问题 | 处理 |
| --- | --- |
| 默认补丁强制要求独立连接文件，实际未启动原生扫描 | 默认改为 DSH Loader 原生发现，空目录也可启动 |
| 单一补丁 YAML 不等于 DSH 有效配置，且路径写死 desktop | 删除 YAML 扫描与固定 profile 路径，使用 `ctx.loader.entries()` |
| YAML 解析器未声明依赖，`!!js` 被当普通字符串 | 删除该依赖，使用条目自身上下文求值原生配置表达式 |
| 已启用官方 MCP 会与管理器重复启动 | 仅接管自身明确停用的官方 stdio 定义，列出其他状态，不改写官方配置 |
| 删除最后一个服务被当作配置错误 | 支持空服务列表并退役最后连接 |
| 并发重载可能旧快照覆盖新配置 | 串行重读和提交，不依赖文件时间戳捷径 |
| 退役租约在运行中的轮次仍可发起新调用 | 新请求和重试拒绝退役连接，已提交请求仍可完成 |
| 退役加载/扫描可能回填旧工具缓存 | 注册前后检查退役状态，缓存写入核对当前定义 |
| 安装包未包含 README 引用的示例 | 把文档与通用示例纳入发布文件清单 |
| README 的占位账户名、无效 JSON 注释、重复夸大测试结论 | 使用真实包名并重写可复制示例与接管边界 |

共享后端状态是明确保留的模式选择，不视为已实现状态隔离。用户需要独立后端进程时应选择 `sharing: session`。原生发现当前仅覆盖 Host Loader 枚举的实际配置，未挂载预设和自定义 MCP 插件不自动接管。

## 回归验证

在本机 DSH 内部模块上运行：

```sh
export DSH_TEST_MODULE_ROOT="$(npm root -g)/@deepseek-ai/dsh/node_modules/@deepseek-ai"
npm test
```

测试输出报告：

| 脚本 | 结果 | 重点 |
| --- | --- | --- |
| `test/integration.mjs` | 通过，报告 30 项检查 | 会话授权、轮次计数、归档、取消、进程组回收 |
| `test/shared-pool.mjs` | 通过，报告 13 项检查 | 共享连接、取消隔离、扫描引用、在途请求保护 |
| `test/config-reload.mjs` | 通过，报告 5 项检查 | JSON 配置变更、退役、坏配置回退 |
| `test/reproduce-stale-reload.mjs` | 通过 | 退役后拒绝新请求、空闲注销和新进程加载 |
| `test/dsh-profile-lifecycle.mjs` | 通过，报告 6 项检查 | 真实 DSH Loader 空启动、状态列表、表达式、父级停用、条目移除事件回收 |

上述为脚本输出的检查数，不等同于测试覆盖率，也不是 DSH 全版本或所有 MCP 服务的验收。

原生生命周期测试使用真实 Cordis Loader、Tools 和 Scope，官方客户端模块用无副作用测试替身替代，连接进程使用本地假服务。没有修改用户正在运行的 DSH 配置，也未下载第三方 MCP。

## 发布边界

本地代码检查不能替代真实 profile 的安装验收。正式发布前需确认仓库名称、npm scope 权限，并在隔离测试 profile 验证 bundle 安装与 MCP 迁移流程。当前 README 的 GitHub/npm 命令明确标注了尚未发布的前提。

包内不应包含主目录绝对路径、凭据、内部会话 ID 或实际服务私有配置；公开 GitHub 用户名与包 scope 是用户明确要求保留的项目身份。敏感信息扫描只能说明已知模式未命中，不能证明任意格式的秘密绝不存在。

剩余待验收：真实有状态 MCP 多会话业务、恢复/fork 的完整业务流、模型自主选择管理工具的稳定性、同进程热升级、跨 Host 缓存并发写入及非 macOS 平台。
