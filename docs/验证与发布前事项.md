# 验证与发布前事项

## 当前交付状态

v2.5 核心、测试、文档由并行代理实施，并经 Lead 集成审查与独立缺陷复查。全量 9 个套件、72 项断言通过（55 项既有权回归 + 17 项 Hub 契约／跨 Host 互斥／真实 AgentLoop）；审查中发现的 2 个高危与 4 个中低风险缺陷已修复并复验，明细见 [CHANGELOG](../CHANGELOG.md)。

本文列出验证方法与通过判据。自动化验证只覆盖假 Hub 与真实 DSH 基础模块；真实 Magpie 进程协作、有状态后端业务、10 分钟闲置回收的实际效果与跨机器共享归属目录仍未验收，不能由本文推断为已通过。

包名为 `@dxc-dxc/dsh-mcp-session-catalog`，MIT 许可。最终版本、运行时/Gate 导出、发布文件清单与测试结果由 Lead 以实际代码核对；文档不能据计划预先宣布发布可用。文档静态检查与核心运行验证应分别记录。

## 四项验收主线

| 主线 | 必须证明的行为 |
| --- | --- |
| 独立模式不退化 | 无 `magpieHub` 或禁用时，原 stdio 配置、表达式、发现、共享/session、轮次、归档、取消、只读重试、文本输出和在途保护继续工作 |
| Hub 会话按需 | 新会话和未 load 会话均无 Hub 业务工具；load 只授予所选逻辑服务，refresh 不授予，native/PTC 路径一致 |
| 初始零网络 | DSH 启动、catalog、resume 不建立 Hub 连接，无 initialize/list/ping/健康检查；显式 load/refresh 才允许请求 |
| Hub 优先且互斥 | 首次 Hub 请求前全部 Hub 归属受管直连退出，跨 Host 确认齐全；无双启、双份工具、隐式备用、自动直连回退 |

新增 Hub 目录项不自动扩权。读取失败、离线、超时或部分列表不当作删除；最后可信归属继续约束新启动。未知 Host 或退出未证实保持 blocked。

## 自动验证方法

使用项目既有测试入口，在已具备 DSH 基础模块的环境指定模块根目录：

```sh
DSH_TEST_MODULE_ROOT=/path/to/dsh/node_modules/@deepseek-ai npm test
```

路径是占位符，不表示所有全局安装布局相同；无需为本任务下载工具或安装真实业务服务。原测试入口与原五组回归保留，新增用例使用本地假服务、假 Hub 和真实 DSH Loader/Tools/Scope。最终命令、退出码及逐组结果由运行者记录，不用脚本存在代替通过。

| 验证组 | 重点判据 |
| --- | --- |
| 原独立回归 | 会话授权、20 轮与覆盖、共享/session、归档、取消隔离、在途保护、配置重读和 stale 退役 |
| 静默与授权 | 初始零网络、resume、native/PTC、A/B 会话与逻辑服务隔离、refresh 不授权、新增服务不扩权 |
| 迁移与 Gate | 首次 Hub 前全体直连清退、跨 Host 屏障、未知状态 blocked、准入与受控重启、队列/审批撤销 |
| 竞态与撤销 | 同步重启、重建、旧异步快照回灌、配置删除/分配取消/禁用工具、schema 与物理代际变化 |
| HTTP 与结果 | JSON/SSE、分页、超时、取消互不影响、最后引用关闭、写不重放、structured/image、原始工具名映射 |
| 配置与信息边界 | 冻结 magpieHub 字段、旧配置无 Hub 依赖、普通 HTTP 不误接管、凭据不落日志/缓存 |

需要记录初始化、子进程、请求提交、工具注册和关闭的时间轨迹，断言直连与 Hub 的活动区间不重叠；只看最终状态或请求总数不足以覆盖中途窗口。

## 样例与文档静态检查

可解析样例包括[独立连接](../examples/servers.example.json)、[Hub 管理器配置](../examples/hub.config.example.json)和[Library 最小形状](../examples/magpie-library.example.json)。仅含占位路径，默认 shared；Library 样例不是可导入生产的用户配置。JSON 语法检查不能验证目标文件存在、服务可用或迁移安全。

检查相对文档链接、配置名称、导出路径和包版本一致；核对 `magpieHub` 没有被误写进连接 `servers` 数组，API 无强制 group，Hub 没有被声称为 session 隔离进程。外部参考文档的能力描述不能自动当作当前安装二进制的实测证据。

## 隔离 profile 迁移验收

完整预检与步骤见[Hub 迁移说明](hub-compatibility.md#迁移预检与步骤)。正式 profile 部署前，应在隔离环境核对所有受管 Host、共享 ownershipDir、Gate 先行挂载、既有会话暂停与受控重启。测试前后保留有效配置备份和时间轨迹，避免把旧 Host 当作已退出。

Hub 首次发现启动其他已分配后端是接受的边界，不是逐项进程冷启动验收失败。外部客户端共用 Hub backend 属于正常共享，不修改其分配或 Magpie 全局开关。本插件卸载只关自己的 HTTP 客户端，不能以停止共享后端验证回收。

## 发布前核对

- 核对实际包版本、安装补丁、runtime-v2.5 与独立 Gate 的公开导出、v2_4 兼容入口及其 locale/icon 资源；确认补丁挂载顺序符合准入要求。
- 检查包清单包含所有核心模块、传输模块、依赖、文档和样例；公开 MCP Client SDK 应正确声明，不能依赖开发机绝对路径。打包 dry-run 不等于发布或安装成功。
- 复核 DSH/Node 版本范围与目标平台限制；既有 macOS 验证不能证明 Linux、Windows 或任意 DSH 版本可用。
- 确认隔离 profile 的安装、配置生命周期、迁移与回收验收，再独立决定用户 profile 部署。npm scope 权限和仓库可用性另行核实，不能据用户名推定发布权限。
- 检查包内容不含凭据、真实主目录路径、会话 ID 或私有配置。只报告实际扫描范围；已知模式未命中不能证明任意秘密都不存在。

## 未验证边界

真实有状态 MCP 的多会话业务、完整 resume/fork 业务流、模型自主触发管理工具的可靠性、生产跨 Host 部署、Gate 升级的受控重启、真实 Magpie backend 单实例及资源收益、非 macOS 平台仍需单独验收。普通目录缓存的跨进程并发写入也不能用 ownershipDir 屏障推定已实现。

Magpie backend 共享和约 10 分钟空闲回收，不等同于每个 DSH session 独立进程；Hub 工具授权隔离不提供后端状态沙箱。Hub resources / prompts、硬实时通知及任意外部插件绕过后的隔离不在本轮承诺中。
