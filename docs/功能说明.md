# 功能说明

> v2.5 已按[已批准合同](approved-plan-v2.5.md)完成实现与集成验收，行为与本文一致；证据与未验证范围见[验证与发布前事项](验证与发布前事项.md)，变更明细见 [CHANGELOG](../CHANGELOG.md)。

## 原独立模式与兼容边界

未由 Hub 管理的 MCP 保留原 stdio 流程。没有 `magpieHub` 或 `enabled: false` 的旧配置不依赖 Hub、Gate 或 HTTP SDK，继续使用原接口。

默认读取 Host 的 `ctx.loader.entries()`，使用 DSH 已合并配置树及其实际枚举的 include 子树，不解析单一磁盘 YAML，也不假定当前 profile 名称。只接管自身明确 `disabled: true` 的官方 `@deepseek-ai/dsh-mcp-client` stdio 条目。条件式停用、停用父级、仍启用的官方客户端和普通非 stdio 条目不接管。未挂载预设和自定义 MCP 插件不会被提升到 Host 全局。

原生表达式使用条目自身的 `entry.evaluate()`，递归求值 `__jsExpr`。读取或求值失败保留上一版有效定义，诊断不输出表达式或配置值。手动 `servers` / `serversFile` 默认关闭原生扫描；显式组合时禁止同一独立服务重名，不能重复配置仍运行的官方客户端。`excludedServers` 保留禁止原生独立服务进入按需目录的作用，不能用来绕开 Hub 归属屏障重新启动同一服务的直连。

独立模式默认 `sharing: shared`，按服务在同 Host 复用进程；`sharing: session` 为每个 Agent 创建独立进程。共享模式共享服务端状态与认证。工具可见性隔离不是后端状态隔离或操作系统沙箱。

## Hub 逻辑服务和互斥归属

启用 `magpieHub` 后，本地 Library 中分配给 `dsh` 且实际由 Hub 提供的 MCP，作为 Hub 逻辑服务进入目录。Hub 物理入口与业务逻辑名分开：`magpie` 是默认入口名，`obsidian` 等是 `mcp_load` 使用的逻辑服务名。

Hub 来源服务初始不注册业务工具。启动、`mcp_catalog` 和 resume 只处理本地元数据及缓存，不向 Hub 发起连接、initialize、tools/list、ping 或健康检查；只有显式 `mcp_load` / `mcp_refresh` 可以唤醒 Hub。恢复或 fork 后仍需按需加载，不能凭缓存或历史对话恢复执行权。

同一逻辑服务只保留一个可加载身份。Hub 归属优先于独立定义，Hub idle、离线、超时、认证错误或工具列表不完整均不能恢复同一服务的直连。确为不同服务的同名项必须明确使用不同逻辑身份，不允许自动双启或双重暴露。

第一次 Hub 请求之前，先阻止**全部 Hub 归属服务**的受管直连发起新请求与重试，排空其在途请求，注销旧工具，并确认进程退出。不能只清退本次请求的服务，因为 Hub 的第一次列表请求可能启动整组已分配后端。

所有受管 Host 通过共享 `ownershipDir` 协调归属代际与清退确认。迁移逻辑状态为：

```text
independent -> retiring-direct -> hub-idle -> hub-connected
                    |               |
                    +---- blocked <-+
```

`hub-idle` 仍属 Hub，不是允许直连的状态。未知 Host、旧 Host 无确认、退出未证实或冲突均为 `blocked`；不得根据等待时长猜测安全、自动剔除旧进程或隐式回退。

## 工具、租约和结果

公开管理工具仍为 `mcp_catalog`、`mcp_load`、`mcp_refresh`，不增加必填 `group`。`mcp_load({server: 'obsidian'})` 只授权调用会话的该逻辑服务；`mcp_refresh` 可借用连接更新目录快照，但不授予业务工具。工具从下一模型步骤起可见。

每个 Agent、逻辑服务各有租约。缓存中的工具名和描述仅用于发现，不能直接执行。业务 wrapper 执行时再次检查调用 Agent、租约、来源和代际，排队或等待审批期间发生撤销也必须拒绝。Hub 工具映射保存完整原始工具名，不从截断或规范化后的公开名反解；合法短名尽量保留，超长或冲突名称需明确映射。

Gate 覆盖已确认的 Hub 来源及需退役的重复直连，在 Agent 准入、最终系统提示与工具定义投影、执行入口检查授权，包括 native 和 PTC 工具路径；不新增对所有非 Hub MCP 的一刀切屏蔽。既有会话迁移需要暂停或受控重启。管理器热重载须保留 Gate；Gate 自身升级需要停止准入并受控重启。公共 API 不足以承诺任意外部插件主动绕过或 Gate 被手动卸载时仍无窗口。

Hub 使用公开 MCP Client / Streamable HTTP 传输，保留宿主的结构化和图像结果投影，转发原调用执行上下文；Hub 业务调用不自动重放。Hub 工具共享后端与认证，不承诺通过 `sharing: session` 创建 Hub 独立进程、独立远端会话或业务状态隔离。

独立 stdio 的原只读重试不变：只读发现最多两次尝试；只读声明或 `readOnlyTools` 命中的工具，在暂时错误时最多三次尝试；写调用不重试。只读标记由服务和配置提供，插件不验证真实副作用。独立结果仍输出文本、嵌入资源文本和结构化内容；非文本内容保留省略提示，默认最多 60000 字符。

共享池持有租约、临时扫描引用和在途计数。一个 Agent 的取消或卸载不影响其他会话；最后引用和在途调用结束才关闭本插件拥有的连接。关闭 Hub 客户端不停止 Magpie Hub 或 backend，也不默认发送远端 `terminateSession`。

## 动态目录、重读和撤销

独立配置仍串行重读提交，不仅凭文件大小或修改时间判断变化。原生模式监听 `loader/config-update`、`loader/partial-dispose`、启动 `ready`，管理和原生工具入口也重读。不支持热应用的部署仍需要重启。

Hub 从本地 Library 提取必要身份、DSH 分配和工具禁用信息，结合显式 load / refresh 取得的 Hub 工具快照动态发现。监听本地文件变化并在操作前重读，不高频网络轮询，不保证变更通知硬实时到达，也不承诺 Hub resources / prompts 支持。

新增 Library 服务不自动授予现有会话。明确删除、取消 DSH 分配或禁用工具时撤销对应授权；schema 或映射改变退役旧租约；端点或认证改变退役旧物理代际。旧异步加载或刷新结果不能回灌新目录。

读取失败、Hub 离线、超时和部分列表均不能当作删除；保留最后可信 Hub 归属，阻止潜在冲突的新启动。独立空目录、删除最后一个服务仍合法；独立定义改变、移除或官方客户端重新启用后，旧租约按原规则 stale，已提交请求可完成，新请求和重试被拒绝。

## 轮次、归档与回收

默认每租约连续 20 个未使用的完成轮次触发回收。有效 `turn/end` 去重，本轮调用 MCP 则归零；达到阈值但 Agent、加载或调用活跃时，等待安全边界。阈值优先级为：服务配置、连接 JSON 顶层、管理器配置、默认 20。`idleTimeoutMs` / `serviceIdleTimeoutMs` 仍拒绝，墙上时间经过本身不触发本插件轮次回收。

归档、Agent 销毁、显式卸载和插件停用释放引用；已提交请求的业务效果无法撤销。Hub 回收仅撤销当前会话工具并释放本插件的 HTTP 引用。Magpie 的约 10 分钟空闲后端回收是另一套共享生命周期，列表访问、其他 DSH 会话或外部客户端的使用都可能保持后端活跃。

## 独立传输与持久化

独立模式保留 stdio 换行 JSON-RPC，默认协议 `2025-06-18`，工具列表最多 100 页并拒绝重复游标，输入缓冲上限 16 MiB。服务端主动 ping 可响应，其他主动请求返回不支持；不承诺工具变更通知自动同步。

服务继承 Host 环境再合并 `env`；`serversFile`、`cacheFile`、`cwd` 支持 `~` 展开，command 和 args 不做 shell 或环境插值。stderr 被排空但不原样记录。macOS 使用独立进程组，终止时先 SIGTERM，再约两秒后 SIGKILL 兜底；主动脱离进程组的守护进程不受组信号控制。迁移要求额外证实被清退进程已退出，不能仅凭发出信号宣布成功。

缓存不保存连接凭据、请求参数或结果，只记录目录与工具摘要。工具描述也可能含敏感信息，不应把秘密写入元数据。普通目录缓存不是跨 Host 协调器；跨 Host 归属屏障使用 `ownershipDir`，不能以缓存文件代替。跨进程普通目录缓存并发写入尚待独立验收。

参数和配置入口见[README](../README.md)，Hub 入口识别、共享边界和迁移步骤见[Hub 兼容性说明](hub-compatibility.md)。
